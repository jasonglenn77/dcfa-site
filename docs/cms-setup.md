# Self-serve CMS (TinaCMS) — how it works & how to run it

The blog is editable through **TinaCMS**. Owners log in with **email** (no GitHub
account needed) at `/admin`, edit posts in a friendly editor, and hit Publish.
Tina commits the change to this repo, Cloudflare rebuilds, and it goes live in a
few minutes.

## The big picture (4 pieces)

```
Owner edits at /admin
        │
        ▼
   TinaCloud   ── saves the edit as a commit ──►   GitHub repo
 (login + save)                                   (source of truth:
                                                   blog posts = Markdown)
                                                          │
                                                          ▼
                                                     Cloudflare
                                              (rebuilds + hosts the site)
                                                          │
                                                          ▼
                                                   Live website
```

- **GitHub** (`jasonglenn77/dcfa-site`) — stores every file, including blog posts
  as Markdown in `src/content/blog/`. The single source of truth.
- **Cloudflare** — builds the site from the repo and hosts it. Auto-rebuilds on
  every push to `main`.
- **TinaCMS** — the editor UI served at `/admin`.
- **TinaCloud** (app.tina.io) — handles owner logins (email) and writes their
  edits back to GitHub. Free tier.

## What's in the repo
- `tina/config.ts` — Tina schema for the **Blog Posts** collection (mirrors
  `src/content.config.ts`). Fields: title, description, publish date, author,
  hero image, draft toggle, rich-text body.
- `tina/tina-lock.json` — generated by `tinacms dev`; **must be committed** (Tina
  Cloud uses it to index content).
- `package.json` scripts:
  - `npm run tina:dev` — local editing at `http://localhost:4321/admin/index.html`.
  - `npm run tina:build` — production build that also generates the `/admin` app.
- Image uploads land in `public/images/uploads/`.
- `/admin` is excluded from search engines via `public/robots.txt`.

## Production setup (already done — for reference)

**TinaCloud** (app.tina.io → project `dcfa-site`):
- Connected to GitHub repo `jasonglenn77/dcfa-site`, branch `main`.
- Site URLs include the production origin (`https://dcfa-site.jason-glenn7.workers.dev`).
- Branch `main` is **indexed** (Configuration → Branches).

**Cloudflare** (Workers & Pages → dcfa-site → Settings → Build):
- Build command: `npm run tina:build`
- Build variables:
  - `TINA_PUBLIC_CLIENT_ID` — from TinaCloud (plaintext)
  - `TINA_TOKEN` — from TinaCloud (secret/encrypted)
  - `TINA_BRANCH` — `main`
  - `NODE_OPTIONS` — `--max-old-space-size=4096` (gives the build enough memory)
- Local secrets live in `.env` (gitignored); `.env.example` documents them.

## How owners use it (day to day)
1. Go to `https://<domain>/admin` and log in with email.
2. **Blog Posts** → edit an existing post or **Create New**.
3. Write text, set a **Hero Image** (upload or pick from the Media library).
4. Click **Save** → it publishes. Live on the site in ~3–5 minutes (a full rebuild).
5. **Draft toggle:** flip a post to *Draft* to save work without it going public.

## Troubleshooting (the two issues we hit during setup)
- **"Branch 'main' is not on TinaCloud" (ERR_CLOUD_CHECK_FAILED):** the branch
  wasn't indexed. Fix in TinaCloud → Configuration → **Branches** → the `⋮` menu
  next to `main` → **Index** (or push a whitespace change to `tina/tina-lock.json`).
  Wait a couple minutes, then retry the Cloudflare build.
- **"JavaScript heap out of memory" during `tinacms build`:** the build needs more
  memory. Fix: the `NODE_OPTIONS=--max-old-space-size=4096` build variable (bump to
  `6144` if it ever recurs).

## Notes for future changes
- Keep `tina/config.ts` and `src/content.config.ts` in sync if you add/rename a
  blog field.
- Want owners to edit *other* sections (team bios, fleet, etc.)? Make those Astro
  data files into Tina collections too — same pattern as the blog.
- High photo volume over time: consider moving media to Cloudflare R2/Images so the
  git repo stays lean. Not needed to start.
